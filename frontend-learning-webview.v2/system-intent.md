# 시스템 개발 의도 (Intent)

## 프로젝트 개요

**프로젝트명:** 학습 콘텐츠 자동 생성 시스템 (Learning Content Auto-Generation System)

**개발 목적:**
프로그래밍 학습 콘텐츠를 수동으로 작성하는 현재 방식은 비효율적이며 일관성 있는 품질 보장이 어렵습니다.
7개 전문 AI 서브에이전트와 오케스트레이션 쉘 스크립트로 구성된 자동화 시스템을 개발하여,
3단계 난이도(Easy/Normal/Expert) 학습 콘텐츠를 고품질로 자동 생성합니다.

## 비즈니스 요구사항

### 현재 상태 (As-Is)
- 수동 콘텐츠 작성: 1개 토픽당 3-5일 소요
- 작성자별 품질 편차 큰 문제
- 5개 섹션 구조 일관성 유지 어려움
- 시각화 컴포넌트 구현 누락 빈번
- 퀴즈 형식 불일치로 파싱 오류 발생

### 목표 상태 (To-Be)
- 자동 콘텐츠 생성: 1개 토픽당 10-20분 소요 (90% 시간 단축)
- AI 에이전트 체인으로 일관된 품질 보장
- 5개 섹션 자동 생성 및 파싱 검증
- 시각화 컴포넌트 자동 생성 + index.ts export
- 100점 척도 품질 평가로 객관적 검증

## 시스템 기능 요구사항

### 핵심 기능 (Core Features)

1. **에이전트 기반 콘텐츠 생성**
   - 7개 전문 에이전트가 각 섹션별 콘텐츠 생성
   - 에이전트 간 Work Status Markers로 상태 공유
   - 순차적 핸드오프로 컨텍스트 전달

2. **품질 검증 시스템**
   - 100점 척도 자동 평가
   - 섹션별 파싱 테스트 (5개)
   - 90점 미만 시 자동 개선 루프

3. **오케스트레이션**
   - 쉘 스크립트로 에이전트 순차 실행
   - Claude CLI 통합 (session 관리)
   - 작업 상태 자동 추적 (Work Status Markers)

4. **확장성**
   - docs/topic/*.md 추가 시 자동 처리
   - 에이전트 독립성 보장 (느슨한 결합)
   - 새 카테고리 추가 시 에이전트 재사용

### 비기능 요구사항 (NFR)

1. **성능**
   - 1개 토픽 생성 시간: 20분 이내
   - 개선 루프 시간: 10분 이내
   - 파싱 테스트 시간: 5초 이내

2. **신뢰성**
   - 품질 점수 90점 이상 달성률: 80% 이상
   - 파싱 테스트 통과율: 100%
   - 에이전트 실행 성공률: 95% 이상

3. **유지보수성**
   - 에이전트 프롬프트는 .md 파일로 버전 관리
   - 쉘 스크립트는 Bash 4.0+ 호환
   - 모든 함수에 주석 및 문서화

4. **확장성**
   - 새 에이전트 추가 시 기존 에이전트 수정 불필요
   - 다국어 지원 (ko → en 확장 가능)
   - 다른 학습 주제로 확장 가능

## 제약사항

### 기술적 제약
1. Claude CLI 사용 필수 (서브에이전트 실행 환경)
2. Bash 4.0+ 호환 (macOS/Linux 환경)
3. Node.js 18+ (파싱 테스트 실행)
4. React 18+ (시각화 컴포넌트 렌더링)

### 비즈니스 제약
1. 기존 마크다운 구조 호환 (5개 섹션)
2. 기존 파싱 로직 재사용 (test/*.mjs)
3. Work Status Markers 형식 유지 (handoff-guide.md)

### 운영 제약
1. 인간 승인 필요 시점: 각 에이전트 계획 단계
2. 최종 검증: 인간 검토 후 Git 커밋
3. 에러 발생 시: 자동 복구 불가, 수동 개입 필요

## 식별된 문제 (해결 필수)

### 문제 1: Visualization 컴포넌트 미렌더링
- **증상**: 시각화 메타데이터 있지만 "준비중" 표시
- **원인**: src/components/visualizations/index.ts export 누락
- **해결**: visualization-writer 에이전트가 export 자동 추가

### 문제 2: Handoff Log 불일치
- **증상**: 파일마다 다른 형식, 미래 시간 상상
- **원인**: 에이전트가 표준 형식 미준수
- **해결**: 표준 형식 강제, 실제 시스템 시간만 사용

### 문제 3: 에이전트 이름 불일치
- **증상**: "completion-validator" 오타로 파일 스킵
- **원인**: 에이전트 이름 검증 부재
- **해결**: 쉘 스크립트에 VALID_AGENTS 검증 로직 추가

### 문제 4: Session ID 중복
- **증상**: "Session ID already in use" 오류
- **원인**: 동일 세션 ID 재사용
- **해결**: 에이전트별 고유 세션 ID 생성

### 문제 5: Quiz 파싱 실패
- **증상**: hints: [], correctAnswer: [] 빈 배열
- **원인**: 필수 헤더 누락 (### Options, ### Hints 등)
- **해결**: quiz-writer 프롬프트에 필수 헤더 명시

## 개발 범위 (Scope)

### In-Scope (개발 대상)
1. 7개 서브에이전트 프롬프트 파일 (.md)
2. 오케스트레이션 쉘 스크립트 (.sh)
3. 파싱 테스트 개선 (test/*.mjs)
4. 통합 테스트 스크립트 (test/integration-test.sh)
5. 시스템 문서화 (docs/aidlc-docs/*.md)

### Out-of-Scope (개발 제외)
1. React 웹앱 수정 (기존 렌더링 로직 유지)
2. 마크다운 구조 변경 (5개 섹션 유지)
3. 새로운 학습 주제 추가 (시스템만 개발)
4. 다국어 번역 기능 (향후 확장)
5. 사용자 인증/권한 관리 (로컬 실행만)

## 개발 방법론

**적용 방법론:** AWS AI-DLC (AI-Driven Development Lifecycle)

**적용 이유:**
- AI(Claude)가 대부분의 코드 생성 담당
- 계획-승인-실행 패턴으로 인간 검증 보장
- 빠른 반복 (시간/일 단위 Bolt)
- 도메인 모델 기반 설계 (에이전트 인터페이스)

**개발 단계:**
1. **Inception (기획)**: 시스템 요구사항 정의, 에이전트 경계 설정
2. **Construction (구축)**: 도메인 모델 → 논리 설계 → 구현 → 테스트
3. **Operations (운영)**: 통합 → 검증 → 배포 → 모니터링
