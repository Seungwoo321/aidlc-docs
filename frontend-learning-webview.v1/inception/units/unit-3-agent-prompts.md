# Unit 3: 에이전트 프롬프트 개선

**우선순위**: P1 (Medium Priority)
**예상 소요 시간**: 3-5일
**담당 영역**: Construction Phase

---

## 목표

기존 에이전트 프롬프트 파일(`.claude/agents/*.md`)에 명시적 I/O 계약, 품질 기준, Work Status Markers 처리 로직을 추가하여 에이전트의 동작을 명확히 정의합니다.

**해결하는 시스템 문제**:
- 에이전트 프롬프트 파일에 명확한 I/O 명세 부재
- 에이전트가 무엇을 입력받고 출력해야 하는지 모호
- Work Status Markers 처리 방법 불명확

---

## 현재 상태 (As-Is)

### 문제점

1. **I/O 명세 부재**
   - 프롬프트에 "무엇을 해야 하는지(What)"만 있고 "무엇을 받는지/만드는지" 명시 부족
   - 예: "개요를 작성하세요" → 입력이 무엇인지, 출력 형식이 무엇인지 불명확

2. **품질 기준 모호**
   - "적절한 길이", "명확하게" 같은 모호한 표현
   - 파서 테스트가 있지만 프롬프트에 반영되지 않음

3. **Work Status Markers 처리 불명확**
   - 마커를 읽고 업데이트하는 방법이 암묵적
   - 실패 시 처리 방법 불명확

4. **검증 로직 부재**
   - 에이전트가 자신의 출력을 자체 점검하는 체크리스트 없음

### 예시: overview-writer.md 현재 상태
```markdown
# Overview Writer

당신의 역할: 학습 콘텐츠의 개요를 작성합니다.

## 작업 내용
- 학습자의 흥미를 끄는 도입부 작성
- 학습 목표 명시
- 핵심 내용 요약

## 주의사항
- 명확하고 간결하게 작성
- 적절한 길이 유지
```
→ 입력, 출력 형식, 품질 기준, 마커 처리 모두 불명확

## 목표 상태 (To-Be)

### 개선 사항

각 에이전트 프롬프트에 **명시적 계약 섹션** 추가:

1. **입력 계약 섹션 (Input Contract)**
   ```markdown
   ## 입력 (Input)

   ### 필수 입력
   - category.yaml에서 읽은 토픽 정보
   - 이전 Filter가 작성한 섹션 (해당되는 경우)

   ### Work Status Markers
   - 확인할 마커: `<!-- Work Request: overview-writer -->`
   - 시작 조건: 상태가 `pending`
   ```

2. **출력 계약 섹션 (Output Contract)**
   ```markdown
   ## 출력 (Output)

   ### 생성할 섹션
   - `## 개요` 섹션 (4개 하위 섹션 포함)
     * Introduction (50자 이상)
     * Why Learn This (3가지 이유)
     * What You'll Learn (3-5개 항목)
     * Prerequisites (선수 지식)

   ### Work Status Markers 업데이트
   - 완료 시: `<!-- Status: completed -->`
   - 다음 Filter 알림: `<!-- Work Request: concepts-writer -->`
   ```

3. **품질 기준 섹션 (Quality Criteria)**
   ```markdown
   ## 품질 기준

   ### 구조적 요구사항 (파서 테스트 기반)
   - [ ] `## 개요` 섹션 존재
   - [ ] 4개 하위 섹션 모두 존재
   - [ ] Introduction 50자 이상

   ### 내용적 요구사항
   - [ ] 학습자 관점에서 작성
   - [ ] 구체적 예시 포함
   - [ ] 전문 용어 사용 시 설명 포함
   ```

4. **자체 점검 체크리스트**
   ```markdown
   ## 작업 완료 전 자체 점검

   출력하기 전 반드시 확인:
   - [ ] 모든 필수 하위 섹션 작성 완료
   - [ ] 품질 기준 모두 충족
   - [ ] Work Status Markers 올바르게 업데이트
   - [ ] 마크다운 문법 오류 없음
   ```

### 개선 전략

**⚠️ 중요: 기존 강점 유지**

기존 프롬프트를 완전히 새로 작성하지 않고, **강점은 유지하면서 명시성만 추가**:

- ✅ 유지: 효과적인 예시, 에이전트의 톤, 핵심 가이드라인
- ➕ 추가: 입력/출력 계약, 품질 기준, 마커 처리, 자체 점검

### 기대 효과

- ✅ 에이전트가 자신의 역할을 명확히 이해
- ✅ 입력 검증 및 출력 자체 점검으로 품질 향상
- ✅ Work Status Markers 처리 표준화
- ✅ 새로운 에이전트 작성 시 템플릿 제공

### 성공 기준

1. 7개 에이전트 프롬프트 모두 개선 완료
2. 각 프롬프트에 입력/출력/품질/자체점검 섹션 추가
3. Unit 1의 Filter 계약과 일치
4. 기존 효과적인 내용 보존
5. 개선 후 파서 테스트 통과

## 리스크 및 고려사항

### 주요 리스크

1. **과도한 명시성으로 창의성 저하**
   - 너무 상세한 계약이 에이전트의 유연성 제한
   - 완화: "무엇(What)"에 집중, "어떻게(How)"는 최소화

2. **프롬프트 길이 증가**
   - 계약 추가로 프롬프트가 길어져 토큰 소비 증가
   - 완화: 핵심만 간결하게 명시

3. **기존 강점 손실**
   - 개선 과정에서 효과적인 부분 제거 가능성
   - 완화: 개선 전 효과적인 부분 명시적 식별

4. **하위 호환성**
   - 개선된 프롬프트가 기존 콘텐츠와 충돌 가능성
   - 완화: 파서 테스트로 검증

### 고려사항

- **점진적 개선**: 한 번에 하나씩 개선하고 테스트
- **A/B 비교**: 개선 전후 콘텐츠 품질 비교
- **롤백 계획**: 문제 발생 시 백업에서 복원
