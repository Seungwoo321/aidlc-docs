# Unit 4: 오케스트레이션 스크립트 개선

**우선순위**: P1 (Medium Priority)
**예상 소요 시간**: 2-3일
**담당 영역**: Construction Phase

---

## 목표

`scripts/content-generator-v6.sh`를 명시적 Filter 계약과 Pipe 메커니즘 기반으로 개선하여 안정성, 재시작 가능성, 확장성을 향상시킵니다.

**해결하는 시스템 문제**:
- 오케스트레이션 로직이 암묵적
- 재시작 및 실패 처리 메커니즘 불명확
- 조건부 Filter 실행 불가능
- 확장성 제한

---

## 현재 상태 (As-Is)

### 문제점

1. **암묵적 실행 로직**
   - Filter 실행 순서가 하드코딩
   - Work Status Markers 처리가 일관되지 않음
   - 각 Filter의 완료 여부 확인 방법 불명확

2. **재시작 메커니즘 부재**
   - 실패 시 어디서부터 재시작할지 수동 판단
   - 부분 완료 파일 처리 방법 모호
   - 재시작 시 중복 작업 가능성

3. **실패 처리 불충분**
   - Filter 실패 감지 방법 불명확
   - 실패 정보 로깅 불충분
   - 재시도 전략 없음

4. **확장성 제한**
   - 새로운 Filter 추가 시 스크립트 대폭 수정 필요
   - 조건부 Filter 실행 불가능 (예: 시각화 건너뛰기)
   - 병렬 처리 불가능

### 예시: 현재 스크립트 구조
```bash
# 현재: 하드코딩된 순차 실행
run_content_initiator
run_overview_writer
run_concepts_writer
run_visualization_writer
run_practice_writer
run_quiz_writer
run_content_validator

→ Work Status Markers 확인 없음
→ 재시작 지점 자동 결정 불가
→ 실패 시 처리 불명확
```

## 목표 상태 (To-Be)

### 개선 사항

**명시적 계약 기반 오케스트레이션**:

1. **Work Status Markers 기반 실행**
   - 마커를 읽어 다음 실행할 Filter 자동 결정
   - 완료된 Filter 건너뛰기
   - 실패한 Filter부터 재시작

2. **재시작 메커니즘**
   - 마지막 완료된 Filter 자동 식별
   - 다음 Filter부터 자동 재시작
   - 중복 작업 방지

3. **강화된 실패 처리**
   - Filter 실패 감지 및 로깅
   - 실패 정보를 Work Status Markers에 기록
   - 재시도 전략 (선택적)

4. **확장 가능한 아키텍처**
   - Filter 목록 설정 파일화
   - 조건부 Filter 실행 지원
   - 새로운 Filter 추가 시 최소 수정

5. **향상된 로깅 및 모니터링**
   - 각 Filter 실행 시간 기록
   - 성능 데이터 수집
   - 진행 상황 실시간 표시

### 기대 효과

- ✅ 재시작 가능성 향상 (실패 지점부터 자동 재시작)
- ✅ 안정성 향상 (명확한 실패 처리)
- ✅ 확장성 향상 (새 Filter 추가 용이)
- ✅ 운영 효율성 향상 (로깅 및 모니터링)

### 성공 기준

1. Work Status Markers 기반 Filter 실행
2. 재시작 시 마지막 완료 지점부터 자동 재개
3. Filter 실패 시 명확한 오류 정보 로깅
4. 새로운 Filter 추가 시 설정 파일만 수정
5. 조건부 Filter 실행 지원 (예: `--skip-visualization`)
