[Question] Free/Pro 플랜 사용자의 주요 사용 시나리오는 무엇인가요?
[Answer] Free 사용자는 기본적인 경제지표 모니터링을 위해 최대 3개 대시보드와 각 6개 위젯을 사용하며, 최근 3년 데이터를 조회합니다. Pro 사용자는 무제한 대시보드/위젯, 전체 기간 데이터, 버전 관리 등 고급 기능을 활용하여 전문적인 분석을 수행합니다.

[Question] 관리자의 주요 업무와 권한 범위는 어떻게 되나요?
[Answer] 관리자는 외부 API에서 조회 가능한 지표를 Supabase에 등록/관리하고, 대시보드 템플릿 생성, 사용자 구독 관리, 플랜별 제한사항 동적 설정, 시스템 모니터링 등의 업무를 수행합니다. 일반 사용자 기능에 더해 Admin Console에 접근할 수 있습니다.

[Question] 위젯 라이브러리와 대시보드 간의 관계는 어떻게 설계되나요?
[Answer] 모든 위젯은 "owned" 모델을 사용합니다. 위젯은 사용자의 위젯 라이브러리에 저장되고, 여러 대시보드에 배치될 수 있습니다. 위젯을 편집하면 해당 위젯을 사용하는 모든 대시보드에 즉시 반영됩니다. 공개 위젯을 추가할 때는 복사하여 내 라이브러리에 저장되므로 원본과 독립적입니다. 대시보드 삭제 시 위젯은 라이브러리에 유지됩니다.

[Question] 대시보드 공유 기능의 세부 요구사항은 무엇인가요?
[Answer] 공유 링크 생성으로 로그인 없이 읽기 전용 대시보드를 공유합니다. 공유 페이지는 대시보드만 전체 화면으로 표시되며, 소유자 플랜의 데이터 조회 기간 제한이 적용됩니다. 링크 재생성 기능과 회원가입 유도 UI를 제공합니다.

[Question] 데이터 조회 시 성능 요구사항이나 응답시간 기준이 있나요?
[Answer] 명확한 성능 기준은 없지만, 사용자 경험 개선을 위해 TanStack Query로 클라이언트 캐싱을 구현하고 레이지 로딩을 적용합니다.

[Question] 위젯당 최대 데이터 포인트 수나 차트 복잡도 제한이 있나요?
[Answer] 데이터 포인트 제한은 없지만, 플랜별로 대시보드 수(Free: 3개, Pro: 무제한), 위젯 수(Free: 대시보드당 6개, Pro: 무제한), 데이터 조회 기간(Free: 3년, Pro: 전체)의 차이가 있습니다. LTTB 알고리즘을 사용하여 대량 데이터 포인트를 효율적으로 처리합니다.

## 시스템 컨텍스트 (README.md 기반)

### 프로젝트 배경

- 경제 지표 대시보드 프로젝트를 Clean Architecture로 전환 중
- 기존 설계(.local/docs/reference)의 핵심 기능과 요구사항은 유지
- 월별, 분기별, 연간 단위의 경제 지표를 모니터링하고 시각화
- Next.js API Route를 통해 외부 데이터 소스 호출
- Supabase로 사용자 인증, 구독 정보, 데이터 소스 관리

### 핵심 제약사항

- 기존 설계의 핵심 기능 유지 (구독 모델, 플랜별 제한사항)
- 대시보드-위젯 구조 유지 (위젯은 데이터가 아닌 파라미터 저장)
- 모든 위젯은 "owned" 모델 (대시보드 삭제 시 위젯은 유지)
- 관리자가 등록한 지표만 사용자가 선택 가능
- SNS 로그인만 지원 (Google, Kakao, Naver 준비중)

### 구독 플랜별 제한

| 데이터 기간 | 최근 3년 | 전체 기간 |
| 자동 임시저장 | ✓ | ✓ |
