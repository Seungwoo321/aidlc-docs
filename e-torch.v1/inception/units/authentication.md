# Authentication Unit

## 단위 개요

**책임**: SNS 로그인, 사용자 인증, 세션 관리 및 프로필 관리

**주요 목표**:
- SNS 로그인 통합: Google, Kakao
- Supabase Auth 활용
- 세션 및 토큰 관리
- 사용자 프로필 관리
- 계정 연결 관리

## 포함된 사용자 스토리

### US1.1: SNS 로그인

**As a** 방문자
**I want to** SNS 계정으로 로그인하기
**So that** 간편하게 서비스를 이용할 수 있다

**검증 기준**:

- Given: 로그인 페이지에서
- When: Google 또는 Kakao 로그인 버튼 클릭
- Then: OAuth 인증을 통해 로그인된다
- And: 사용자 프로필이 생성/로드된다
- And: 첫 로그인 시 자동 회원가입
- And: 같은 이메일의 기존 계정이 있으면 자동 통합

### US1.2: 프로필 관리

**As a** 일반 사용자
**I want to** 내 프로필 정보를 관리하기
**So that** 개인 정보를 최신으로 유지할 수 있다

**검증 기준**:

- Given: 프로필 설정 페이지에서
- When: 정보를 수정하고 저장하면
- Then: 프로필 정보가 업데이트된다
- And: 변경사항이 즉시 반영된다
- And: 연결된 모든 SNS 계정 표시
- And: 추가 SNS 계정 연결 옵션 제공

## SNS 계정 연결 정책

### 자동 계정 통합
- 같은 이메일로 다른 Provider 로그인 시 자동 통합
- Supabase Account Linking 활용
- 사용자 확인 없이 즉시 통합

### 수동 계정 연결
- 프로필 페이지에서 추가 SNS 계정 연결 가능
- 이미 로그인한 상태에서 다른 Provider 추가
- 연결 해제 기능 제공

## 단위 간 의존성

### 입력 의존성

- **Supabase Auth**: OAuth 인증 및 세션 관리
- **OAuth Providers**: Google, Kakao 인증

### 출력 제공

다른 Unit에서 사용 가능한 기능 (상세 인터페이스는 integration_contract.md 참조):

- **모든 Unit에 제공**:
  - 인증 상태 확인
    - 현재 로그인 사용자 정보 조회
    - 세션 유효성 검증
  - 권한 확인
    - 사용자 역할 확인 (user/admin)
    - 보호된 리소스 접근 권한 검증
  - 세션 관리
    - 토큰 갱신
    - 로그아웃 처리
  - SNS 계정 연결 관리 (US1.2)
    - 추가 SNS 계정 연결
    - 연결된 SNS 계정 해제
    - 연결된 계정 목록 조회

- **Admin Console Unit에 제공**:
  - 관리자 권한 검증
  - 역할 기반 접근 제어
  - 계정 상태 관리
    - 사용자 계정 활성화/비활성화
    - 비활성 계정 로그인 차단

## 인증 플로우

### SNS 로그인 프로세스
1. 사용자가 SNS Provider 선택
2. OAuth 인증 페이지로 리다이렉트
3. Provider에서 인증 완료 후 콜백
4. Supabase가 세션 생성 및 토큰 발급
5. 사용자 프로필 로드 또는 생성
6. 앱으로 리다이렉트

### 세션 관리
- Access Token 유효 기간: 1시간 - Supabase 기본값
- Refresh Token 유효 기간: 7일
- 자동 토큰 갱신
- localStorage에 세션 유지

### 계정 통합 플로우
1. 새로운 Provider로 로그인 시도
2. Supabase가 동일 이메일 감지
3. 자동으로 기존 계정에 identity 추가
4. 사용자는 어느 Provider로든 로그인 가능

## 보안 요구사항

- 사용자 인증 토큰이 안전하게 저장되어야 한다
- 전송 중 인증 데이터가 보호되어야 한다
- XSS 공격으로부터 보호되어야 한다
- 세션 고정 공격이 방지되어야 한다
- CSRF 공격으로부터 보호되어야 한다
- 인가되지 않은 OAuth 리다이렉트가 차단되어야 한다
- 비활성화된 계정(status: 'inactive')의 로그인이 차단되어야 한다
- 계정 상태 변경은 관리자 권한을 가진 사용자만 수행할 수 있어야 한다
